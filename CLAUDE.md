# Default Alive Calculator

Native macOS calculator for PG's "default alive" test: SwiftPM, no Xcode project, no
dependencies. The only persisted state is the last input (UserDefaults, bundle id
`local.DefaultAliveCalculator`): each box's text and unit (`cash`, `expenses[Unit]`,
`revenue[Unit]`, `growthPercent[Unit]`, `growthDollar[Unit]`), `growthLinear`, `taxesOn`,
`taxPlaces` (ids), `taxShares` (typed shares, kept after a place is removed), `chartShown`.

## Layout

- `Sources/DefaultAliveCore/`: everything testable. `Projection` (compounding + linear), `Units`, `Breakevens` (the "alive if" column), `Taxes`, `Formatting`, `Parsing` (numbers + arithmetic), `Readout` (all text under the divider + hints), `BalanceCurve` (chart data), `CalculatorState` (the form's behavior: unit cycling, separate %/$ growth boxes, taxes, commit, clear).
- `Sources/DefaultAliveCalculator/`: AppKit shell + key monitor (`App.swift`), persistence (`CalculatorModel`), SwiftUI view (`CalculatorView.swift`, tokens in `enum Style`), the tax checklist popover (`TaxPicker.swift`), Swift Charts (`BalanceChart`), `--snapshot` (`Snapshot.swift`), `--selftest` (`SelfTest.swift`).
- `Sources/DefaultAliveCore/TaxPlaces.json`: every state + DC and the cities that tax before profit. Generated by `node research/places.mjs` from `research/taxes-YYYY-MM.json` (one Opus agent per state, `research/workflow.js`); the curation calls (exclusion vs cliff thresholds, Hawaii GET as pass-through) live in that script. Compiled into the app (`.embedInCode` in Package.swift) and imported by `model.js`, so there's one copy.
- `design/`: the browser mock. `index.html` (UI, CSS variables named like `Style`), `model.js` (JS twin of the core), `presets.json` (gallery states + shared spec for readout text and hints), `shot.mjs` (headless screenshots).

## Design loop (use this for any UI change)

1. **Mock it in the browser first.** Edit `design/index.html` (and `design/model.js` if behavior changes). Run `make preview-shot` and Read `build/preview.png` (whole page: each design tile beside the app's current rendering, light and dark) or `build/preview-live.png`. For one exact state: `node design/shot.mjs 'http://127.0.0.1:8765/design/?preset=dead&theme=light' out.png '#live-window'`. The user watches the same page via `make preview`; it live-reloads on save.
2. **Get the user's OK on the mock** before touching Swift, unless they've spelled out exactly what they want.
3. **Port it.** CSS variables map 1:1 onto `enum Style`; `model.js` functions map onto `DefaultAliveCore` with the same names. If wording or hints change, update `expect` in `design/presets.json`; it's the spec for both sides. Logic changes are test-first in `Tests/DefaultAliveCoreTests`.
4. **`make`**: Swift + node tests, build, refresh `build/snapshot.png`, reinstall to `~/Applications`, relaunch. Then `make preview-shot` again: the app columns should match the design columns. Keyboard changes: `make selftest`.

## Traps

- **The two models must stay identical.** `model.js` is a line-for-line twin of the Swift core; `make test` checks both against `presets.json`. Rounding is explicit on both sides: ties away from zero for display, and toward the safe side for hints ("≥" up, "≤" down; $241.04 needed must read "≥ $242").
- **Seeing the app**: `screencapture` needs Screen Recording and System Events keystrokes need Automation/Accessibility; this terminal has neither. Use `make snapshot` for looks and `make selftest` for keys (both permission-free and never touch saved input). Selftest needs keyboard focus for ~3s: it waits for 5s of no keyboard/mouse input first, and if the user takes focus mid-run it reports `INTERRUPTED` rather than false FAILs. Don't read FAILs from an interrupted run as bugs; rerun when idle.
- **Keyboard**: all handled in the NSEvent monitor in `App.swift`, not AppKit's key-view loop (which would also stop on the unit buttons when keyboard navigation is on). Clear all: Esc, C, keypad Clear (keyCode 71), or ⌘⌫ only when no box has the cursor; inside a box ⌘⌫ passes through to delete-to-start, which is why the Edit menu's Clear All shortcut is Esc (a ⌘⌫ menu shortcut would fire first). Tab / Return: next box, Shift for previous, wrapping; Return also compacts an expression ("163+5" → "168"), Tab doesn't. Forward selects all; backward and arrows park the cursor at the end. Clicking empty space deselects (`onTapGesture` on the form; selftest checks boxes still take clicks).
- **Boxes take arithmetic**: `evaluate()` in Parsing.swift / model.js. Unary minus only at the start or after "(", so "--5" stays invalid.
- **Box text is raw; commas and units are drawn.** The four boxes are `NumberField` (an AppKit NSTextField), not SwiftUI TextField: SwiftUI's uses a private field editor (`_SystemTextFieldFieldEditor`) that ignores `windowWillReturnFieldEditor`, and it won't display a rewritten string while editing. `GroupingFieldEditor` kerns a gap after every third digit and draws a grey comma in it, and drops typed/pasted "$", "%", ","; `NumberFieldCell` draws the same commas when not editing. Comma positions come from `groupBreaks` (twin in model.js; the mock uses a contenteditable `numberBox` with CSS-generated commas). Focus moves are `FocusRequest`s applied by the field itself (makeFirstResponder, then select), so there's no waiting on SwiftUI.
- **Taxes** (`Taxes.swift` / model.js `withTaxes`): only taxes that bite before profitability, receipts taxes and fixed yearly amounts, per place in `TaxPlaces.json`; income taxes are zero until breakeven so they can't change the verdict. Each place: `rate` × your share of revenue counted there (share box only if `rate` > 0), a threshold judged on *current* revenue (cliff, or `excess` = only the amount above is taxed), plus `perYear`. Sums run in catalog order on both sides so the last bit matches. Default: DE (most venture-backed startups are Delaware corporations). Hints under taxes are converted back to pre-tax numbers (`Taxed.gross`). The checklist filter (`TaxCatalog.matching` / `matchingPlaces`): every word must be in the name or state name, or equal the state code; "Add all"/"Remove all" act on what it shows. Re-check the research yearly (see `research/places.mjs`).
- **The tax checklist is a popover**, a window of its own, so the key monitor (main window only) never sees its keys: "c" types, Esc closes it natively. It fades out over a few hundred ms; selftest waits 1s before checking it's gone.
- **Dragging the profitability dot** sets growth via `dragProfitPoint`: as growth varies the dot moves on a straight line (C = k·T), so the pointer is projected onto it in screen space, pinned at the zero line (the default-alive minimum; past it the dot would vanish). Axes freeze during a drag except the time axis widening toward that line. `make selftest` finds the dot through `SelfTestProbe`; SwiftUI's `.global` space on this window is measured from the window's top edge *including* the 28pt title bar, so convert with `window.frame.height`, not the content height.
- **$ growth** adds to the Revenue box's figure per growth period: linear in the period (an earlier version squared it, so $50/wk read as $136k/yr). Changing the Revenue box's unit re-expresses the $ growth box.
- **Swift Charts colors**: `.secondary` / `.quaternary` resolve against the accent color there (blue gridlines). Use explicit `Color.primary.opacity(...)`.
- **Axis edge labels** must hang inward (`AxisValueLabel(anchor:)`), or Charts drops the "0" and truncates the last label.
- **TextField text** is AppKit underneath: `NSColor.textColor` (100% black/white), not SwiftUI's 85% label color. The mock's colors were measured from snapshot pixels; re-measure rather than guess if they drift.
- **Screenshots**: Chrome's `--headless --screenshot` fires on a virtual-time budget and caught the page before the gallery decoded; `shot.mjs` waits for `document.body.dataset.ready`. The snapshot is pinned to 2x because the render scale otherwise follows the main display (1x on the external monitor).
- **Running app**: `make` kills and relaunches it. Input survives because it's written to UserDefaults on every keystroke.
